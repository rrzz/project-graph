# System-coverage Project Graph orchestrator prompt

Build a whole-system Project Graph for this repository. Do not equate source
directory coverage with system coverage. First create a mandatory coverage
matrix for client, edge, gateway, identity/API, real-time transport,
authoritative runtime, persistence/lifecycle, background/status, service
connectivity, security/abuse, observability, build, delivery/recovery,
verification, and material external vendors.

Each row must be `covered`, `deferred`, or `absent`; no unassigned rows. Use
bounded coverage workers for matrix surfaces and frontier workers for risky
cross-boundary questions. Workers are source-read-only and can write only
candidate reports outside assertion globs. One orchestrator re-opens evidence,
resolves identities, writes reviewed assertions, locks evidence, and owns any
completion claim.

Use FTS-backed `query` before graph traversal. A reviewed unlocked graph is
usable, and a `"reused": true` build is successful; locking and Git verification
are explicit acceptance/handoff controls, not ordinary query prerequisites.

For each covered surface capture source ownership, inbound/outbound data,
authority and state, controls, verification, and a graph question. Require
gold questions that prove the public request path, real-time state path,
persistence/lifecycle path, and build/delivery/recovery path when applicable.
Never use line-number anchors or turn confidence into evidence.
